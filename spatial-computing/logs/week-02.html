Week 02 Spatial Computing Research Log

Dates

March 9, 2026 - March 15, 2026

Representation Comparison

I selected two different environment sources for the first controlled experiments: a real Scaniverse bathroom point cloud and a manually modeled apartment. The point cloud represented noisy, raw sensed space, while the apartment represented cleaner, human-modeled geometry. This created a stronger comparison than treating every spatial input as interchangeable.

Point-Cloud Pipeline

I organized the Scaniverse .ply file and defined a Python workflow using NumPy and Open3D: load the data, downsample it, construct a proximity graph, identify connected components, and run BFS, Dijkstra, and A*. The original scan contained 681,270 points. The first abstraction reduced it to approximately 9,842 points and used a tractable subset of 1,200 graph nodes.

Initial Measurements

  • 681,270 original point-cloud points
  • Approximately 9,842 downsampled points
  • 1,200 graph nodes
  • 6,437 graph edges
  • 1,061 nodes in the largest connected component
  • BFS reached all 1,061 nodes in that component
  • Dijkstra path: approximately 18 nodes, cost 4.72
  • A* path: approximately 17 nodes, cost 4.68

What Changed

The project moved from collecting spatial files to testing how algorithms reason over a deliberately constructed abstraction. BFS became the reachability baseline, Dijkstra established uniform-cost path behavior, and A* used spatial heuristics to guide the search. The modeled apartment, containing approximately 17.3 thousand vertices and 17.1 thousand triangles, provided a cleaner comparison case for later experiments.
